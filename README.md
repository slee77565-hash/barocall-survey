# 실험 설문 웹 프로토타입

불리한 요금에서 AI 가격결정자의 완충 효과가 요금 산정 근거에 따라 달라지는지를 검증하는
2(가격결정 주체) × 2(산정 근거) 피험자 간 실험의 설문 도구입니다.

파일은 `index.html` 하나뿐이며 외부 라이브러리를 쓰지 않습니다. 어떤 정적 호스팅에도 그대로 올릴 수 있습니다.

---

## 1. GitHub Pages에 올리기

1. GitHub에서 새 저장소를 만듭니다. 예: `barocall-survey`
2. `index.html`을 저장소 최상위에 올립니다.
3. 저장소 **Settings → Pages**로 이동합니다.
4. Source를 **Deploy from a branch**, Branch를 **main / (root)** 로 지정하고 저장합니다.
5. 1~2분 뒤 `https://<계정명>.github.io/barocall-survey/` 로 접속됩니다.

## 2. 두 가지 링크

| 용도 | 주소 | 특징 |
|---|---|---|
| 참가자용 | `.../barocall-survey/` | 네 조건에 무작위 배정, 문항 코드 숨김 |
| 동료 검토용 | `.../barocall-survey/?review=1` | 문항 코드 표시, 우측 하단에서 조건 전환 가능 |

특정 조건만 보려면 주소 뒤에 조건을 붙입니다.

```
?agent=ai&basis=market      AI × 실시간 시장 수요
?agent=ai&basis=data        AI × 개인 이용 데이터
?agent=human&basis=market   요금정책 담당자 × 실시간 시장 수요
?agent=human&basis=data     요금정책 담당자 × 개인 이용 데이터
```

검토 요청 시에는 `?review=1` 링크를 보내고, 우측 하단 **조건 전환** 버튼으로 네 조건을 모두
비교해 달라고 안내하시면 됩니다. 특히 **담당자 × 개인 이용 데이터** 조건이 어색하게 읽히지
않는지가 중요한 점검 대상입니다.

## 3. 응답 수집 설정

기본값은 저장 서버가 없는 상태입니다. 이 경우 참가자가 마지막 화면에서 응답 파일(JSON)을
내려받아 연구자에게 전달하게 됩니다. 동료 검토 단계에서는 이대로도 충분합니다.

유료 패널로 정식 조사를 할 때는 `index.html` 상단의 `CONFIG.ENDPOINT`에 수집 주소를 넣습니다.

```js
const CONFIG = {
  ENDPOINT: "https://script.google.com/macros/s/....../exec",
  ...
};
```

### Google 스프레드시트로 받는 방법

1. 새 Google 스프레드시트를 만들고 **확장 프로그램 → Apps Script**를 엽니다.
2. 아래 코드를 붙여넣습니다.

```javascript
function doPost(e) {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];
  var d = JSON.parse(e.postData.contents);
  var a = d.answers, m = d.meta;
  if (sheet.getLastRow() === 0) {
    sheet.appendRow(['시각','주체','근거','매개순서','소요초'].concat(Object.keys(a)));
  }
  sheet.appendRow(
    [m.finishedAt, m.agent, m.basis, (m.mediatorOrder||[]).join('-'), m.durationSec]
      .concat(Object.keys(a).map(function(k){ return a[k]; }))
  );
  return ContentService.createTextOutput('ok');
}
```

3. **배포 → 새 배포 → 웹 앱**을 선택하고, 액세스 권한을 **모든 사용자**로 설정한 뒤 배포합니다.
4. 발급된 URL을 `CONFIG.ENDPOINT`에 넣습니다.

응답 자료가 개인정보를 포함하지 않도록 설계되어 있으나, 수집 시트의 공유 범위는 연구자 본인으로
제한하시기 바랍니다.

## 4. 도구에 이미 반영된 설계 원칙

- **무작위 배정**: 접속할 때마다 네 조건 중 하나에 배정됩니다.
- **자극 순차 노출과 진행 잠금**: 시나리오는 문단이 하나씩 나타나고 마지막에 앱 화면과 안내 문구가 드러납니다. 이 순서가 끝나기 전에는 다음 버튼이 잠깁니다. 단순 대기 타이머와 달리, 참가자가 **조작에 해당하는 안내 문구가 화면에 나타나는 것을 반드시 보게** 됩니다. 전체 약 17초가 걸리며, 노출 간격은 `runSequence()`의 `GAP`과 `TAIL`로 조정합니다.
- **다시 보기**: 순차 노출이 끝나면 다시 볼 수 있습니다. 반복 횟수는 응답 자료의 `replays`에 기록됩니다.
- **문항 순서 무작위화**: 확증적 매개변수 세 묶음의 제시 순서와 각 묶음 내 문항 순서를 무작위화합니다. 배정된 순서는 응답 자료의 `mediatorOrder`에 기록됩니다.
- **조건별 문구 치환**: 가격결정 주체 표현이 조건에 따라 자동으로 바뀌며, 한국어 조사도 받침에 맞춰 처리됩니다.
- **네 조건의 평행성**: 안내 문구는 주어와 근거만 다르고 서술어와 문장 구조가 동일합니다.
- **되돌아가기 없음**: 이전 화면으로 돌아갈 수 없습니다. 문항을 보고 시나리오를 다시 읽으면 기억이 아니라 재독에 근거한 응답이 됩니다.
- **응답 누락 방지**: 모든 문항에 응답해야 다음으로 넘어갑니다.
- **의인화 문항 분기**: AI 조건에서만 제시됩니다.
- **주의점검**: `AT1` 문항이 포함되어 있습니다.
- **디브리핑**: 마지막 화면에서 가상의 앱과 요금제였음을 안내합니다.

수집되는 자료에는 응답값과 함께 조건, 매개변수 제시 순서, 화면별 체류 시간, 시나리오 다시 보기 횟수, 전체 소요 시간이 포함됩니다. 시나리오 화면의 체류 시간(`timing.B3`)이 노출에 걸리는 최소 시간에 지나치게 가깝다면 서둘러 넘긴 응답으로 볼 수 있습니다.

## 5. 아직 확정되지 않은 부분

`JD1`~`JD3`(판단받는 느낌)과 `EX1`~`EX3`(착취성 지각)은 Duani, Barasch, & Morwitz(2024)의
원문 측정문항을 확보하지 못해, 해당 논문이 제시한 구성개념 정의에 근거해 자체 개발한 척도입니다.
특히 `JD`는 확증적 매개변수이므로 원문을 확보하게 되면 본조사 이전에 교체합니다.

## 6. 파일럿에서 확인할 것

| 점검 대상 | 근거 문항 |
|---|---|
| 가격결정 주체 조작 | MC1 |
| 산정 근거 조작 | MC2 |
| 요금의 불리성 | MC3 |
| 셀별 시나리오 현실성 | RE1~RE3 (네 조건 평균 비교) |
| 개인관련성 | SR1~SR3 |
| AI 비의인화 | AN1~AN2 |
| 척도 품질 | 전 척도의 분산·신뢰도·분포 |
| SI와 EX의 변별 | SI1~SI3, EX1~EX3 |

결과변수의 조건 간 차이나 효과 방향은 자극 수정의 기준으로 사용하지 않습니다. 다만 문항의
응답 분포, 천장·바닥 효과, 내적 일관성, 문항 이해도 같은 측정도구의 기초적 특성은 점검합니다.

## 7. 목표 표본

셀당 30~40명, 총 120~160명입니다. 조건이 넷이므로 셀당 인원에 4를 곱한 값이 전체 표본이 됩니다.
